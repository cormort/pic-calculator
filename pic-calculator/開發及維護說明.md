# 圖片計算機 - 開發及維護說明

## 專案概述

圖片計算機是純前端的表格辨識與驗算工具（沒有後端，圖片不上傳）：
- 圖片上傳／手機拍照 → 瀏覽器內 OCR 辨識表格
- 智慧合計與欄／列手動驗算
- 乘法關係驗算（單價 × 數量 ＝ 金額；表頭認得就自動驗，可一鍵套用算出的金額）
- 同格式表格連續處理時沿用上一張的驗算設定
- 待核對清單（低信心／看不出是數字／合計不符／乘法不符合成一個佇列）、格子復原、匯出 CSV
- 點格子放大原圖對照、PDF 逐頁辨識、驗算方向（自動分組）、一次驗兩個方向
- PWA 可安裝為手機 App、離線使用
- 頁首分流「📊 表格驗算／📝 文字金額」（記在 localStorage `pcAppMode`），載入圖後自動辨識只跑選定模式
- 表格「🧮 點格加總」與文字模式共用浮動加總視窗

## 技術架構

```
pic-calculator/
└── static/                # 全部是靜態檔，GitHub Pages 直接提供
    ├── index.html        # 主頁面：UI、互動控制、PDF／批次／原圖對照流程
    ├── styles.css        # 全域與響應式樣式
    ├── validator.js      # Validator 手動與分組驗算、數字整理、選取角色邏輯
    ├── table_builder.js  # buildTable 切欄切列、貼上文字解析、PDF 文字層處理
    ├── text_amounts.js   # 文字金額模式（中文單位換算、金額萃取與原位編輯）
    ├── template.js       # 沿用上一張表格驗算設定
    ├── smart_total.js    # 智慧合計、層級／跨頁／憑證驗算（純函式，可用 node 測試）
    ├── ocr-worker.js     # Web Worker：版面偵測、透視矯正、格線偵測、OCR、表格結構
    ├── models/           # 同源託管 PP-OCRv6 / PP-DocLayout-S / SLANet 模型
    ├── manifest.json     # PWA 資訊清單
    └── sw.js             # Service Worker 離線快取與同源隔離標頭
tests/                     # node 單元測試（不需瀏覽器與模型）
```

| 層面 | 技術 |
|------|------|
| OCR | PP-OCRv6（ppu-paddle-ocr + ONNX Runtime Web，WebGPU／WASM） |
| 前端 | Vanilla JS + CSS，無建置步驟 |
| PWA | Service Worker + Manifest |

## 本機開發

```bash
cd pic-calculator/static && python3 -m http.server 8000
# 開啟 http://127.0.0.1:8000
```

OCR 模型（PP-OCRv6、PP-DocLayout-S、SLANet）託管在 `static/models/`（同源載入以避開手機跨網域問題），推論函式庫（onnxruntime-web、ppu-paddle-ocr、opencc-js、pdf.js）從 CDN 下載，第一次需要網路或可先按「預先下載模型」。
手機測試相機需要 HTTPS：直接用線上版，或以 `ngrok http 8000` 之類的工具轉成 HTTPS。

## PWA 安裝

- iOS：Safari → 分享 → 加入主畫面
- Android：Chrome → 選單 → 安裝應用程式

## 辨識流程（全部在瀏覽器，`static/ocr-worker.js` + `static/index.html`）

```
圖片 → 版面模型找表格範圍(quad) → 四角點透視矯正 → PP-OCRv6 文字辨識
     → 格線偵測（直線/橫線）→ 跨格線字框切開重辨識 → 切列切欄組成表格
     → 數字整理（全形/千分位/混淆字）→ 智慧合計驗算
```

幾個容易踩到的點（改動前請先讀）：

| 位置 | 做什麼 | 為什麼 |
|------|--------|--------|
| `normalizeForLines()`（worker） | 找格線前把每個像素除以附近平均亮度 | 線要比兩側暗 20 階才算；昏暗或陰影下的淡格線會整條漏掉。只給 `detectLines()` 用，OCR 的輸入不變 |
| `splitStraddling()`（worker） | 字框跨過格線時，沿線切兩半各自重辨識 | 項次「1-1」右對齊緊貼科目「主持人費」時，偵測器會把整串框成一個字，整張表從該列開始左右錯位 |
| `splitBoxAtLine()`（index.html） | 上面那步的備援：沒有影像時按字寬比例拆 | 單一個字的裁切常常認不出來，靠這條路補 |
| 數字框一律不拆 | 整格是數字就不切 | 拆出「6」＋「46,219」會讓整欄驗算錯 |
| `repairNumericCells()`（index.html） | 全形轉半形、千分位句點修正、O→0／l→1 | 實拍常把 `25,000` 讀成 `25.000`，parseFloat 會變成 25，整張表差一千倍 |
| 空欄移除（`buildTable`） | 整欄（含表頭）都沒有字就刪掉 | 陰影、紙緣被當成格線時會多切出空欄，表頭與數字錯開一格 |
| 標題列移除 | 第一條橫線以上、且沒有數字的列 | 表格標題（「113年度…明細表」）不屬於表格 |
| `unparsedNumericCells()` | 金額欄裡「有字但不是數字」的格：紅虛線、排除在驗算外、在橫幅列出 | 這類格若默默被排除，合計會不符，使用者會以為是表格算錯（假錯誤） |
| `suspiciousTotalRows()` | 標籤像合計卻認不得（「小計」讀成「小」）：主動問「是合計列嗎？」並可一鍵指定 | 標籤讀壞時整列不會被驗算，而且不會有任何錯誤訊息 |
| `isAmountColumn()` | 只有「形狀像金額」的欄才納入驗算 | 項次欄（1、1-1、2-1）也會被解析成數字，拿它加總或把「小」當壞數字都只是雜訊 |
| 驗算涵蓋範圍 | 橫幅固定顯示「涵蓋 N 個合計列、M 格；K 格排除在外」 | 避免「沒驗到」被誤讀成「驗過且正確」 |
| `SmartTotals.multiplyCheck()` | 表頭有「單價／數量／金額」時驗乘法；不符時給「改成 X」與「單價／數量應為 Y」兩種可能 | 加總驗算對「被加數本身讀錯」完全無感（金額少一個 0，小計也跟著相符或一起錯），只有乘法關係抓得到 |
| `normalizeAndSharpen()`（worker） | 估計淺底紙張並正規化亮度，搭配輕微 3×3 銳化（滾動緩衝省記憶體） | 6 張實測拿掉這一步格級 95.5%→94.5%、數字 98.2%→95.1% |
| `reviewQueue()`（index.html） | 把低信心、看不出是數字、合計不符、乘法不符合成一個待核對佇列，依「會不會破壞驗算」排序 | 原本是四套流程（按鈕／橫幅清單／自己找橘線），核對時要分別處理還容易漏 |
| `columnShape()`（template.js） | 記下每欄「幾成是數字」，沿用設定時比對 | 欄數、表頭都對得上但金額欄已變成數量欄時，硬套角色會產生「錯了卻顯示驗算正確」 |
| `autoTotalIndexOf()`（validator.js） | 沒明確指定合計時，回傳「最後點選的那一欄／列」 | 手勢預設：點欄號都是加項、最後一個是等於。`selIndices()` 必須把自動合計從加項裡剔除 —— 舊版回 `[2,3,3]`，同一欄既當加項又當合計，期望值把自己加進去，永遠驗不過 |

| `APP_VERSION`（index.html）＋ `CACHE_NAME`（sw.js） | 一起換版號 | 模組 worker 與 PWA 會快取 `ocr-worker.js`；沒帶版本參數時改版會「改了沒反應」 |
| `openPdf()` / `renderPdfPage()` | PDF 用 pdf.js 轉成 2 倍解析度的 PNG，再走原本的 `loadFile()`（帶 `{fromPdf:true}`，否則會把 `pdfDoc` 清掉、換頁列消失） | 表格跨頁拆開會亂，所以一次一頁；pdf.js 只在選了 PDF 時才動態載入 |
| `scheduleWorkerWarmup()`（index.html） | 若所選模型已於本機快取，頁面閒置時透過 `warmup` 預先初始化 Worker／ONNX session | 減少第一張送圖時的啟動延遲，且未快取時不觸發額外下載 |


| `reviewQueue()`（index.html） | 把低信心、看不出是數字、合計不符、乘法不符合成一個待核對佇列，依「會不會破壞驗算」排序 | 原本是四套流程（按鈕／橫幅清單／自己找橘線），核對時要分別處理還容易漏 |
| `pushUndo()` / `undoLast()` | 手改與一鍵修正都推一筆 undo（Ctrl/⌘+Z 或按鈕）；格子內編輯時不攔，讓瀏覽器原生復原 | 改錯沒有任何退路是實務上最卡的地方 |
| `exportCsv()` | 匯出 CSV（UTF-8 BOM） | 沒有 BOM，繁中 Windows 的 Excel 打開會變亂碼 |
| `squashLabel()` / `templateKey()` | 比對科目與表頭時忽略「、」括號與全形半形標點 | OCR 常漏讀「、」，「不動產、廠房及設備」對不上會讓沿用設定與合計判定失效 |

模型精度：`tiny` 6MB／`small` 30MB（預設）；已移除實測表現較差的 `medium`（139MB）與 TATR 備援模型。快速模式信心偏低時結果區會出現
「🔁 改用標準模型重辨識」按鈕。

## 驗算操作（欄／列）

表格上方有一條「選取托盤」：

```
點欄號／列號時   [＋ 加項] [− 減項] [＝ 合計]   清空
目前選取： 欄2 ＋   欄3 ＋   欄5 ＝
```

1. 先點角色（預設「加項」）
2. 再點表格的**欄號**（上方）或**列號**（左側）套用；同一個角色再點一次＝取消，換角色直接再點
3. 合計只會有一個；托盤上的 chip 點一下就取消該欄／列
4. 沒指定合計時沿用「最後一個加項」，托盤會註明
5. Shift＋點＝整段連續加項；表頭可用 Tab 聚焦、Enter／空白鍵套用

內部狀態在 `sel`（`col` / `row` 各有 `plus`、`minus`、`total`），
`selIndices()` 會把合計排在最後給 `Validator.validate()`，所以驗算邏輯本身沒動。

### 點格加總

表格上方「🧮 點格加總」開啟後，點格子依序切換 加（藍框）→ 減（橘框）→ 取消，
浮動視窗即時顯示加總。這個模式下格子不能編輯（`contenteditable` 關掉），關掉模式即恢復；
點選存在 `cellPicks`（`'r,c'` → ±1），換表時清空，改了數字會用新值重算。

## 文字金額模式（`analyzeText()`）

給審查意見這類一般文字用，範圍刻意限定為**一張照片、最多一頁 A4**，不照搬
budget-opinion-reviewer 的完整功能（沒有段落篩選、DOCX/PDF 萃取流程）。

1. OCR 全文（worker 收到 `textOnly: true`，跳過表格結構模型）
2. 平均信心 < 0.85 時把圖轉 180° 再辨識一次，取信心高的（紙放反拍的照片）
3. `wordsToText()`：字框依 y 分行、行內由左到右，**整段接起來不換行**（折行會把「1,430｜萬3千元」切成兩筆）；
   點後剛好 3 位且接萬／億／元的「5.431萬」改回「5,431萬」（OCR 常把逗號讀成點）
4. `extractAmounts()`：依「。；」分句、每個「元」切一筆，數字＋兆億萬千百拾換算成元
5. 每筆**預設不計入**（段落金額常是比較基準），點按鈕切換 ＋／－／不計；表格「內容」欄可直接改，
   改動寫回上方全文（全文是唯一資料來源）再重算
6. 關鍵字篩選只影響表格與上方合計；浮動視窗加的是所有計入項目，不受篩選影響

## 驗算邏輯（前端）

位於 `static/index.html` 中的 `Validator` 物件：

```javascript
// 橫向驗算（欄）
case 'horizontal':
  inputs.forEach(i => sum += value * sign);

// 縱向驗算（列）
case 'vertical_row':
  inputs.forEach(r => sum += value * sign);
```

容差計算：一般加減與乘法差異不超過 `max(1.0, |實際值| * 0.00001)` 視為正確；除法（比率）差異不超過 `max(0.01, |實際值| * 0.001)` 視為正確。

## 沿用上一張的驗算設定（同格式表格連續處理）

換下一張圖（辨識新圖或按「🆕 重新辨識」）之前，`rememberTemplate()` 會記下這一張的設定；
新表辨識完由 `applyTemplate()` 判斷能不能套用。

| 記什麼 | 怎麼對到新表 |
|------|------|
| 欄角色（＋／−／＝） | 欄號照用 |
| 列角色 | 依科目名稱找；找不到或有兩列同名就不沿用列設定 |
| 按過「是，當合計」的列 | 依標籤找（「小」被截斷時下一張常常也是「小」） |

套用前 `matchTemplate()` 一定先比對：**欄數相同**、**表頭有 60% 以上相同**（比對時忽略數字，
所以「113年1月」與「113年2月」視為相同）。不符就只提示、不套用 —— OCR 多切一欄時「欄4」
已不是原本那一欄，盲目套用會變成「錯了卻顯示驗算正確」。橫幅上的「不要沿用」會清掉記住的設定。
這一張沒做任何設定時，保留更早那一張的設定。

## 維護指南

| 檔案 | 職責 |
|------|------|
| `index.html` | UI、事件處理、PDF／批次／原圖對照與畫面串接 |
| `styles.css` | 頁面樣式與響應式佈局 |
| `validator.js` | `Validator`、數字整理、雜字剝除、選取角色操作 |
| `table_builder.js` | `buildTable()` 切欄切列、貼上解析、PDF 文字層處理 |
| `text_amounts.js` | 文字金額模式萃取與原位替換 |
| `template.js` | 沿用上一張驗算設定 |
| `ocr-worker.js` | 版面模型、透視矯正（`RECT_MAX_SIDE=1920`）、`detectGridLines()` 2×2 min-pool 找線、`recognizeBoxes()` 批次字框重認、結構模型 |
| `smart_total.js` | 合計標籤判斷、候選試算、層級與憑證驗算 |
| `sw.js` | 離線快取與同源隔離；改了殼的檔案清單或快取策略時要升 `CACHE_NAME` |

### 常見問題

| 問題 | 解決方案 |
|------|----------|
| 相機無法開啟 | 需使用 HTTPS 網址 |
| PWA 無法安裝 | 檢查 manifest.json、sw.js 是否正確載入 |
| OCR 辨識錯誤 | 旋轉、傾斜會影響，可用「左轉／右轉」與四角框選修正，或改用標準模型／高解析截圖 |
