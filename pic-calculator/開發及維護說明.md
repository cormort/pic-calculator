# 圖片計算器 - 開發及維護說明

## 專案概述

圖片計算器是純前端的表格辨識與驗算工具（沒有後端，圖片不上傳）：
- 圖片上傳／手機拍照 → 瀏覽器內 OCR 辨識表格
- 智慧合計與欄／列手動驗算
- 同格式表格連續處理時沿用上一張的驗算設定
- PWA 可安裝為手機 App、離線使用

## 技術架構

```
pic-calculator/
└── static/                # 全部是靜態檔，GitHub Pages 直接提供
    ├── index.html        # 主頁面：UI、切欄切列、數字整理、驗算
    ├── ocr-worker.js     # Web Worker：表格偵測、透視矯正、格線偵測、OCR
    ├── smart_total.js    # 智慧合計（純函式，可用 node 測試）
    ├── manifest.json     # PWA 資訊清單
    └── sw.js             # Service Worker 離線快取
tests/                     # node 單元測試（不需瀏覽器與模型）
```

| 層面 | 技術 |
|------|------|
| OCR | PP-OCRv6（ppu-paddle-ocr + ONNX Runtime Web，WebGPU／WASM） |
| 前端 | Vanilla JS + CSS，無建置步驟 |
| PWA | Service Worker + Manifest |

## 本機開發

```bash
cd pic-calculator/static && python3 -m http.server 8000
# 開啟 http://127.0.0.1:8000
```

模型與函式庫從 CDN（jsDelivr、Hugging Face）下載，第一次需要網路。
手機測試相機需要 HTTPS：直接用線上版，或以 `ngrok http 8000` 之類的工具轉成 HTTPS。

## PWA 安裝

- iOS：Safari → 分享 → 加入主畫面
- Android：Chrome → 選單 → 安裝應用程式

## 辨識流程（全部在瀏覽器，`static/ocr-worker.js` + `static/index.html`）

```
圖片 → 版面模型找表格範圍(quad) → 四角點透視矯正 → PP-OCRv6 文字辨識
     → 格線偵測（直線/橫線）→ 跨格線字框切開重辨識 → 切列切欄組成表格
     → 數字整理（全形/千分位/混淆字）→ 智慧合計驗算
```

幾個容易踩到的點（改動前請先讀）：

| 位置 | 做什麼 | 為什麼 |
|------|--------|--------|
| `splitStraddling()`（worker） | 字框跨過格線時，沿線切兩半各自重辨識 | 項次「1-1」右對齊緊貼科目「主持人費」時，偵測器會把整串框成一個字，整張表從該列開始左右錯位 |
| `splitBoxAtLine()`（index.html） | 上面那步的備援：沒有影像時按字寬比例拆 | 單一個字的裁切常常認不出來，靠這條路補 |
| 數字框一律不拆 | 整格是數字就不切 | 拆出「6」＋「46,219」會讓整欄驗算錯 |
| `repairNumericCells()`（index.html） | 全形轉半形、千分位句點修正、O→0／l→1 | 實拍常把 `25,000` 讀成 `25.000`，parseFloat 會變成 25，整張表差一千倍 |
| 空欄移除（`buildTable`） | 整欄（含表頭）都沒有字就刪掉 | 陰影、紙緣被當成格線時會多切出空欄，表頭與數字錯開一格 |
| 標題列移除 | 第一條橫線以上、且沒有數字的列 | 表格標題（「113年度…明細表」）不屬於表格 |
| `unparsedNumericCells()` | 金額欄裡「有字但不是數字」的格：紅虛線、排除在驗算外、在橫幅列出 | 這類格若默默被排除，合計會不符，使用者會以為是表格算錯（假錯誤） |
| `suspiciousTotalRows()` | 標籤像合計卻認不得（「小計」讀成「小」）：主動問「是合計列嗎？」並可一鍵指定 | 標籤讀壞時整列不會被驗算，而且不會有任何錯誤訊息 |
| `isAmountColumn()` | 只有「形狀像金額」的欄才納入驗算 | 項次欄（1、1-1、2-1）也會被解析成數字，拿它加總或把「小」當壞數字都只是雜訊 |
| 驗算涵蓋範圍 | 橫幅固定顯示「涵蓋 N 個合計列、M 格；K 格排除在外」 | 避免「沒驗到」被誤讀成「驗過且正確」 |

模型精度：`tiny` 6MB／`small` 30MB（預設）／`medium` 139MB。信心偏低時結果區會出現
「🔁 用高精度模型重辨識」按鈕。

## 驗算操作（欄／列）

表格上方有一條「選取托盤」：

```
點欄號／列號時   [＋ 加項] [− 減項] [＝ 合計]   清空
目前選取： 欄2 ＋   欄3 ＋   欄5 ＝
```

1. 先點角色（預設「加項」）
2. 再點表格的**欄號**（上方）或**列號**（左側）套用；同一個角色再點一次＝取消，換角色直接再點
3. 合計只會有一個；托盤上的 chip 點一下就取消該欄／列
4. 沒指定合計時沿用「最後一個加項」，托盤會註明
5. Shift＋點＝整段連續加項；表頭可用 Tab 聚焦、Enter／空白鍵套用

內部狀態在 `sel`（`col` / `row` 各有 `plus`、`minus`、`total`），
`selIndices()` 會把合計排在最後給 `Validator.validate()`，所以驗算邏輯本身沒動。

## 驗算邏輯（前端）

位於 `static/index.html` 中的 `Validator` 物件：

```javascript
// 橫向驗算（欄）
case 'horizontal':
  inputs.forEach(i => sum += value * sign);

// 縱向驗算（列）
case 'vertical_row':
  inputs.forEach(r => sum += value * sign);
```

容差計算：差異不超過 `max(1.0, |實際值| * 0.005)` 視為正確。

## 沿用上一張的驗算設定（同格式表格連續處理）

換下一張圖（辨識新圖或按「🆕 重新辨識」）之前，`rememberTemplate()` 會記下這一張的設定；
新表辨識完由 `applyTemplate()` 判斷能不能套用。

| 記什麼 | 怎麼對到新表 |
|------|------|
| 欄角色（＋／−／＝） | 欄號照用 |
| 列角色 | 依科目名稱找；找不到或有兩列同名就不沿用列設定 |
| 按過「是，當合計」的列 | 依標籤找（「小」被截斷時下一張常常也是「小」） |

套用前 `matchTemplate()` 一定先比對：**欄數相同**、**表頭有 60% 以上相同**（比對時忽略數字，
所以「113年1月」與「113年2月」視為相同）。不符就只提示、不套用 —— OCR 多切一欄時「欄4」
已不是原本那一欄，盲目套用會變成「錯了卻顯示驗算正確」。橫幅上的「不要沿用」會清掉記住的設定。
這一張沒做任何設定時，保留更早那一張的設定。

## 維護指南

| 檔案 | 職責 |
|------|------|
| `index.html` | UI、事件處理、`buildTable()` 切欄切列、`repairNumericCells()`、`Validator`、沿用設定 |
| `ocr-worker.js` | 版面模型、透視矯正、格線偵測、跨格線拆框重辨識 |
| `smart_total.js` | 合計標籤判斷、候選試算 |
| `sw.js` | 離線快取；改了殼的檔案清單或快取策略時要升 `CACHE_NAME` |

### 常見問題

| 問題 | 解決方案 |
|------|----------|
| 相機無法開啟 | 需使用 HTTPS 網址 |
| PWA 無法安裝 | 檢查 manifest.json、sw.js 是否正確載入 |
| OCR 辨識錯誤 | 旋轉、傾斜會影響，可用「左轉／右轉」與四角框選修正，或改用高精度模型 |
